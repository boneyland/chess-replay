# Import

[Spec](../spec.md) › what is built. Getting a game in: Import game (files, pasted PGN or FEN) and Lichess game links. Reading a position from a picture is in [Position from image](position-from-image.md).

## Import game

Built 2026-11-04. The dock's primary button, **Import game** (it replaced Load game; Settings › Game has it too), opens one dialog (`ImportDialog` in `app/free-board.jsx`) with every way a game or position comes in from outside, so the Dock menu keeps only starting points and tools. From a game in progress it asks first (`guard`), and what the dialog then opens doesn't ask again.

- **Drop a PGN or choose a file** (Choose a file on a touch screen): opens the file picker, as Load game did (a PGN, with this page's analysis, notes or Queen files too). Files dropped while the dialog is open load at once; the page's drop overlay shows over the dialog. The dialog closes once files come back from the picker or a drop.
- **Position from image**: opens that dialog in its place (hidden where the reader can't run); its Cancel from picking or cropping comes back to Import game.
- **The paste box** ("PGN, FEN or Lichess link"): Open or Ctrl+Enter opens it, Enter is a new line, Esc closes the dialog. `ImportCore.read` (`app/import-core.js`) tells them apart: one line that looks like a FEN (seven `/` in its first field, or a lone `[FEN "…"]` tag) is read by `EditCore.fromFen`; anything else must build as a PGN. A PGN opens as a loaded game (tags, comments, evals, a `[FEN]` start; the first game of several, and Settings › Game › **Game in PGN** picks another, dropping the analysis); a legal FEN opens the free board at it; a well-formed but illegal one opens Edit position on it, which says what's wrong, and whose Cancel comes back to Import game with the pasted text. Text that is neither gets the reader's message under the box and changes nothing (a web address that isn't a Lichess link: "That link isn’t a Lichess game, broadcast or study."). Ctrl+V on the page still doesn't load anything (decided earlier: too easy to set off).
- Not in it: My games (it resumes games in progress, which isn't importing; it stays under Play).
- A Lichess game link in the same box: see [Lichess game import](#lichess-game-import).

## Lichess game import

Built 2026-11-04. Finished Lichess games open here as a loaded game, never ongoing ones. Checked against Lichess on 2026-11-04: every endpoint below answers without a token and with `access-control-allow-origin: *`; a Masters game from the explorer (`lichess.org/jYSkjcuG`, Carlsen–Caruana 2019) exports from `lichess.org/game/export` like any Lichess game; a game not finished has `[Result "*"]` (a live broadcast round's boards too).

- **Links** (`LichessCore.gameLink`, pure, with or without `https://` and `www.`): a game `lichess.org/<id>` (8 characters; a player's 12-character link is cut to 8), `/game/<id>`, either with `/black` or `/white` and `#<ply>`, exported from `lichess.org/game/export/<id>` with its clocks and evals; a broadcast game `lichess.org/broadcast/<tour>/<round>/<roundId>/<gameId>` and a study chapter `lichess.org/study/<studyId>/<chapterId>`, both from `lichess.org/api/study/<id>/<chapter>.pgn`; a broadcast round `…/<roundId>` (no game; `lichess.org/broadcast/<roundId>` alone too) from `lichess.org/api/broadcast/round/<roundId>.pgn`, and a whole study `lichess.org/study/<studyId>` from `lichess.org/api/study/<studyId>.pgn`, both as a list; the three study and round exports ask for clocks, comments and variations (a round's export leaves the variations, its best lines, out unless asked). A few words that look like ids (analysis, training…) aren't links.
- **Import game's paste box** takes a link (`ImportCore.read` → `{ link }`): "Fetching from Lichess…" under the box while it's fetched (Open disabled; Cancel or Esc stops it), then a finished game opens as a loaded game (`lichess-<id>.pgn`) with Lichess's evals and clocks when it has them, the board turned as Lichess shows it (the Flip setting: from Black's side for `/black`, else White's), `#32` opening paused after ply 32. A game with no result says "This game is still being played: it can be opened once it ends." Only standard chess and Chess960 open (`ImportCore.pgn`, which a pasted PGN goes through too): a `Variant` tag other than Standard, From Position or Chess960 says "That’s a Crazyhouse game: only standard chess and Chess960 open here.", and a fetched game that doesn't build gets the PGN reader's message, both before the dialog closes or Flip changes. Offline, not found (404), a private study (403), Lichess busy (429) and other answers each get a message under the box; the dialog stays open with the link.
- **A round or a study** shows its games in place of the paste box (a round not started yet, whose PGN is one placeholder with no players, says there are no games there yet), one button per game, "White – Black · 1–0" (and its board, from a `Round` tag like `9.4`); a game with no result shows greyed, "playing", and can't be opened, as does a variant game, greyed with its variant's name in place of the result (the note says why the greyed ones are). **Back** goes to the paste box with the link still in it. A round with no finished game says so.
- **Opening explorer**: under its games, **Open games: Here · On Lichess** (`TWEAK_DEFAULTS.explorerOpen = 'here'`, remembered). Here: a click opens Import game on the game's link and fetches it at once (from a game in progress `guard` asks first); a middle click, a Ctrl/⌘/Shift-click or On Lichess opens Lichess in a new tab as before.
- Nothing is sent to Lichess until a link is opened or clicked: no setting. `lichess.org` is already in the CSP's `connect-src`; `sw.js` passes it through, so fetched games aren't kept offline.
- Tests: Node, `tests/lichess-core.test.cjs` (links, lists, the result check) and `tests/import-core.test.cjs`; live, Import game with Lichess's answers faked by replacing the page's `fetch` for `lichess.org` (a finished game, `#ply` and `/black`, an unfinished one, a 404, a round list), and the explorer's switch.
