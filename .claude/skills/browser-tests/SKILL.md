# Live browser tests and the demo video

- `node --test tests/live/site.test.cjs` - smoke tests against the live site in Chromium, then Firefox (Playwright, real mouse input; screenshots in `tests/out/live/`). `LIVE_ONLY=<regex>` runs only the subtests whose names match (node's name patterns can't reach them), `LIVE_URLS=local` tests a build of this checkout served by `tests/live/serve.cjs`, `LIVE_BROWSERS` picks the browsers (`webkit` too: Playwright's own WebKit with the iPhone 13 profile on phone tests; on this laptop only in podman, below), `LIVE_CDN_DIR` serves React from local npm packages where cdnjs is blocked, `FIREFOX_PATH=playwright` runs Playwright's own Firefox (a cloud machine without a stock Firefox). On a Claude Code cloud machine (`CCR_AGENT_PROXY_ENABLED`) Firefox's contexts skip certificate checks (Chromium's still check), as Playwright's Firefox doesn't trust the HTTPS proxy's CA: cdnjs, Google Fonts and the service worker then work without `LIVE_CDN_DIR`, and only the offline test fails in Playwright's Firefox (its reload gets `NS_ERROR_OFFLINE`). Here: sandbox disabled, Playwright via `NODE_PATH` (an npx copy under `~/.npm/_npx`); Chromium is the ungoogled-chromium flatpak, Firefox the installed Developer Edition over WebDriver BiDi. GitHub Actions runs it with `LIVE_URLS=local` in the runner's Chrome and Firefox and in Playwright's WebKit (the `browsers` jobs, Playwright pinned there). Never in deploy builds
  - WebKit on this laptop: Playwright's own WebKit build doesn't run natively on Fedora (it's built for Ubuntu and links ICU 74, libjpeg 8 and libjxl 0.8), but it runs in podman, in the image `mcr.microsoft.com/playwright:v1.63.0-noble` (~2 GB; the Playwright version installed in the container must match the image's). Run it with the sandbox disabled, the container capped and a MemAvailable watchdog:

    ```bash
    setsid podman run --rm --memory=4g --ipc=host -v $PWD:/repo:Z -v ~/.cache/claude-tmp/pwnm:/pw:Z -w /repo \
      -e NODE_PATH=/pw/node_modules -e LIVE_URLS=local -e LIVE_BROWSERS=webkit -e LIVE_ONLY='<regex>' \
      mcr.microsoft.com/playwright:v1.63.0-noble bash -c 'cd /pw && [ -d node_modules/playwright ] || npm install --no-save --no-package-lock playwright@1.63.0; cd /repo && node --test tests/live/site.test.cjs' > wk.log 2>&1 & pid=$!
    while kill -0 $pid 2>/dev/null; do [ $(awk '/MemAvailable/{print int($2/1024)}' /proc/meminfo) -lt 2200 ] && { kill -9 -$pid; podman kill -a; }; sleep 3; done
    ```

    playwright@1.63.0 is cached in `~/.cache/claude-tmp/pwnm`. The container is much slower than CI: the whole WebKit run takes over 40 minutes, tests that count frames fail (the cloud Go deeper test needs 5 frames a second and gets 2), and so do some timing-sensitive ones that pass in CI (the hover-preview and flipped-board line-preview tests failed there on `main` on 2026-11-17). Run `main` the same way before blaming a change. `LIVE_ONLY` on a subtest that reuses the shared `page` (e.g. Keyboard shortcuts) fails, because the subtest that opens the page is skipped. Epiphany (WebKitGTK) against `tests/live/serve.cjs` is still the user's manual check

- `node --test tests/live/android.test.cjs` - smoke tests in Chrome on Android (Playwright's `_android` over adb, the local build reached through `adb reverse`, taps as DevTools touch events): needs one adb device with Chrome, debuggable or with chrome://flags › Enable command line on non-rooted devices. GitHub Actions' `android` job runs it on an API 34 google_apis emulator; the user's phone has Chrome as well as Firefox Beta, so this can run on it; this laptop can't run an emulator
- `node --test tests/live/ios.test.cjs` - smoke tests in Apple's Safari on an iOS Simulator (WebdriverIO over `safaridriver`; macOS with Xcode only, after `sudo safaridriver --enable`; `IOS_DEVICE` names the Simulator, default iPhone 17 or the newest iPhone it has): what Playwright's Linux WebKit can't show (Safari's own full screen, Apple's H.264 encoder, iOS's own bars). Its tap-tap move failed from 2026-11-02 until 2026-11-17: a captured touch's pointerup came at 0,0 there (the touchend had the real point), so each tap read as a drag to the board's corner; the board now lets go where the drag last was (`liftPoint`) and the job passes. If the move fails again, the test logs every pointer event of each tap with its point and tries a slow tap and script-dispatched pointer events too. The page is served as `ios.html`, the page with a console-error logger in front, as WebDriver can't read Safari's console. GitHub Actions' `ios` job runs it on `macos-latest` (free, as the repo is public); one of `main`'s required checks since 2026-11-17; it can't run on this laptop
- `node --test tests/live/safari.test.cjs` - smoke tests in desktop Safari on macOS (WebdriverIO over `safaridriver`, after `sudo safaridriver --enable`; no Xcode needed): the desktop layout at a 1440×900 page (the window is sized from what the page measures), mouse clicks and drag moves, Play/Pause, stepping, the keyboard (playhead, Moves panel, Settings tabs, Esc), a setting kept over a reload, Flip board, Import game (typed PGN), a promotion, full screen, the service worker, H.264 (about 80 s of tests, 2026-11-08). Safari focuses no button on a click, so a click leaves the focus on the page: the Import game test checks that its dialog still takes Tab and Esc then. Served as `safari.html`, with the same console logger as `ios.html`. GitHub Actions' `safari` job runs it on `macos-latest`, with whichever Safari that image ships; one of `main`'s required checks since 2026-11-08; it can't run on this laptop
- `node media/record-demo.cjs` - re-records `media/demo.mp4`, the README's ~65 s showcase video, zooming in on the panels worth reading (Byrne–Fischer 1956 from `media/demo-game.pgn`), from a build served by `tests/live/serve.cjs`; sandbox disabled, Playwright via `NODE_PATH`, ffmpeg. GitHub plays a README video inline only when uploaded through its web editor, so a new recording is dragged into the README there
