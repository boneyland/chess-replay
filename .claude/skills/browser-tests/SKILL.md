# Live browser tests and the demo video

- `node --test tests/live/site.test.cjs` - smoke tests against the live site in Chromium, then Firefox (Playwright, real mouse input; screenshots in `tests/out/live/`). `LIVE_ONLY=<regex>` runs only the subtests whose names match (node's name patterns can't reach them), `LIVE_URLS=local` tests a build of this checkout served by `tests/live/serve.cjs`, `LIVE_BROWSERS` picks the browsers (`webkit` too: Playwright's own WebKit with the iPhone 13 profile on phone tests; it can't run on this Fedora machine, as its build is for Ubuntu and links ICU 74, libjpeg 8 and libjxl 0.8, which Fedora lacks (tried 2026-10-30, removed again), so it runs in GitHub Actions' `webkit` job, and the user checks by hand in Epiphany (WebKitGTK) against `tests/live/serve.cjs`), `LIVE_CDN_DIR` serves React from local npm packages where cdnjs is blocked, `FIREFOX_PATH=playwright` runs Playwright's own Firefox (a cloud machine without a stock Firefox). On a Claude Code cloud machine (`CCR_AGENT_PROXY_ENABLED`) Firefox's contexts skip certificate checks (Chromium's still check), as Playwright's Firefox doesn't trust the HTTPS proxy's CA: cdnjs, Google Fonts and the service worker then work without `LIVE_CDN_DIR`, and only the offline test fails in Playwright's Firefox (its reload gets `NS_ERROR_OFFLINE`). Here: sandbox disabled, Playwright via `NODE_PATH` (an npx copy under `~/.npm/_npx`); Chromium is the ungoogled-chromium flatpak, Firefox the installed Developer Edition over WebDriver BiDi. GitHub Actions runs it with `LIVE_URLS=local` in the runner's Chrome and Firefox (`browsers` job, Playwright pinned there). Never in deploy builds
- `node --test tests/live/android.test.cjs` - smoke tests in Chrome on Android (Playwright's `_android` over adb, the local build reached through `adb reverse`, taps as DevTools touch events): needs one adb device with Chrome, debuggable or with chrome://flags › Enable command line on non-rooted devices. GitHub Actions' `android` job runs it on an API 34 google_apis emulator; the user's phone has only Firefox Beta, and this laptop can't run an emulator
- `node --test tests/live/ios.test.cjs` - smoke tests in Apple's Safari on an iOS Simulator (WebdriverIO over `safaridriver`; macOS with Xcode only, after `sudo safaridriver --enable`; `IOS_DEVICE` names the Simulator, default iPhone 17 or the newest iPhone it has): what Playwright's Linux WebKit can't show (Safari's own full screen, Apple's H.264 encoder, iOS's own bars). Its tap-tap move fails on purpose until checked on a real iPhone: WebDriver's touch taps reach the board's React handler on the right squares and its state takes e2, yet the page never draws the selection and e4 plays nothing, while pointer events dispatched by the page's script play the move (2026-11-02, 12 runs), so either iOS taps are broken or safaridriver's input is. The page is served as `ios.html`, the page with a console-error logger in front, as WebDriver can't read Safari's console. GitHub Actions' `ios` job runs it on `macos-latest` (free, as the repo is public); it can't run on this laptop
- `node media/record-demo.cjs` - re-records `media/demo.mp4`, the README's ~65 s showcase video, zooming in on the panels worth reading (Byrne–Fischer 1956 from `media/demo-game.pgn`), from a build served by `tests/live/serve.cjs`; sandbox disabled, Playwright via `NODE_PATH`, ffmpeg. GitHub plays a README video inline only when uploaded through its web editor, so a new recording is dragged into the README there
