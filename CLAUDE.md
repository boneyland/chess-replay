# Chess Replay

Browser player for annotated chess games, at https://chess-replay.onrender.com/. Split out of `~/projects/chess-animator` (Python/Manim renderer) on 2026-10-17; that repo must stay checked out next to this one.

## Commands
- `node build.cjs` - writes `out/site/` (page, two Stockfish files, two WebP encoder files, web app manifest + icons from `app/icons/`, service worker `sw.js` (from `app/sw.js`), link-preview image `app/og-image.png`, whose `og:image` URL is Render's `RENDER_EXTERNAL_URL`, or the Render site in a local build)
- `node --test --test-concurrency=1 tests/*.test.cjs` - JS tests (also writes `tests/out/`); GitHub Actions (`.github/workflows/test.yml`) runs them on every push to `main` and every pull request, and the Render build before building
- `node --test tests/live/site.test.cjs` - smoke tests against the live site in Chromium, then Firefox (Playwright, real mouse input; screenshots in `tests/out/live/`). `LIVE_ONLY=<regex>` runs only the subtests whose names match (node's name patterns can't reach them), `LIVE_URLS=local` tests a build of this checkout served by `tests/live/serve.cjs`, `LIVE_BROWSERS` picks the browsers (`webkit` too: Playwright's own WebKit with the iPhone 13 profile on phone tests; it can't run on this Fedora machine, as its build is for Ubuntu and links ICU 74, libjpeg 8 and libjxl 0.8, which Fedora lacks (tried 2026-10-30, removed again), so it runs in GitHub Actions' `webkit` job, and the user checks by hand in Epiphany (WebKitGTK) against `tests/live/serve.cjs`), `LIVE_CDN_DIR` serves React from local npm packages where cdnjs is blocked, `FIREFOX_PATH=playwright` runs Playwright's own Firefox (a cloud machine without a stock Firefox). On a Claude Code cloud machine (`CCR_AGENT_PROXY_ENABLED`) Firefox's contexts skip certificate checks (Chromium's still check), as Playwright's Firefox doesn't trust the HTTPS proxy's CA: cdnjs, Google Fonts and the service worker then work without `LIVE_CDN_DIR`, and only the offline test fails in Playwright's Firefox (its reload gets `NS_ERROR_OFFLINE`). Here: sandbox disabled, Playwright via `NODE_PATH` (an npx copy under `~/.npm/_npx`); Chromium is the ungoogled-chromium flatpak, Firefox the installed Developer Edition over WebDriver BiDi. GitHub Actions runs it with `LIVE_URLS=local` in the runner's Chrome and Firefox (`browsers` job, Playwright pinned there). Never in deploy builds
- `node --test tests/live/android.test.cjs` - smoke tests in Chrome on Android (Playwright's `_android` over adb, the local build reached through `adb reverse`, taps as DevTools touch events): needs one adb device with Chrome, debuggable or with chrome://flags › Enable command line on non-rooted devices. GitHub Actions' `android` job runs it on an API 34 google_apis emulator; the user's phone has only Firefox Beta, and this laptop can't run an emulator
- `../chess-animator/.venv/bin/python -m unittest tests/check_browser_json.py` - checks the browser's analysis JSON against the Python pipeline; run after the JS tests
- `node media/record-demo.cjs` - re-records `media/demo.mp4`, the README's ~65 s showcase video, zooming in on the panels worth reading (Byrne–Fischer 1956 from `media/demo-game.pgn`), from a build served by `tests/live/serve.cjs`; sandbox disabled, Playwright via `NODE_PATH`, ffmpeg. GitHub plays a README video inline only when uploaded through its web editor, so a new recording is dragged into the README there
- Preview: `node tests/live/serve.cjs` (out/site on 127.0.0.1:8765, answering as Render does) with the sandbox disabled (a sandboxed server is unreachable from Playwright, and `file://` is blocked); phone layout = 390×844 viewport

## Publishing (only when asked)
Render: a static site (chess-replay) built from this repo on every push to `main` (publish `out/site`). Its settings live in `render.yaml` (build command with the tests first, rewrite `/` → `/chess-game-video.html`, Cache-Control header, build filters, PR previews): the service is linked to a Blueprint, so a push that changes the file syncs them; change them there, not in the dashboard (a dashboard edit holds only until the next sync, and the build filters were found emptied there on 2026-10-22, so every push deployed). A sync sets every field the file gives and clears some it leaves out (an omitted `previews` turns PR previews off). Auto-deploy is on, so a merged PR that touches the page goes live there at once. PR previews are on: each PR gets a temporary deployment link posted on it

## Workflow
- Changes to the app (anything that changes the page as served: `app/`, `vendor/`, `openings/`, `build.cjs`, `render.yaml`…) go on a branch (`claude/<topic>`) as small commits, pushed with a pull request against `main`: the PR is how the user previews the change on Render before it goes live, and the record to look back on. Merging it is what deploys (Render builds `main`). Everything else (docs, CLAUDE.md, README, tests-only or tooling changes, the demo video) is committed straight to `main`, no branch or PR. Remote is `origin` (github.com/boneyland/chess-replay); push and open a PR only when asked
- PR descriptions never include a Claude Code session URL (a `claude.ai/code/…` link)
- Visual changes: screenshot desktop (1440×900) and phone layouts and show the PNG paths before committing; the user usually tweaks sizes
- Screenshots taken for a change go in its PR description too, each with a caption (viewport, browser). `gh` can't upload attachments, so they live on the orphan branch `pr-screenshots` (no workflow files, so no CI; Render builds only `main`) under `pr-<N>/`, embedded as `https://github.com/boneyland/chess-replay/raw/pr-screenshots/pr-<N>/<file>.png`. Add them with git plumbing, leaving the working tree alone: a temporary `GIT_INDEX_FILE` seeded from the branch tip (`git read-tree origin/pr-screenshots`), `git hash-object -w` + `git update-index --add --cacheinfo`, `write-tree`, `commit-tree -p origin/pr-screenshots`, then `git push origin "${c}:refs/heads/pr-screenshots"` (braces, not just quotes: zsh reads `$c:r` as the `:r` modifier even inside double quotes)
- The user views the app in desktop Firefox. Checks here can run in Firefox too (Developer Edition, `firefox.launch({ channel: 'moz-firefox', executablePath: '/usr/bin/firefox-devedition' })`): for layout changes (CSS columns, overflow, height caps) screenshot both browsers; a capped-height multi-column box once spilled a fifth Settings column in Firefox that Chromium never showed. Playwright's Firefox has no phone emulation (no `isMobile`, a fine pointer), and its headless full screen is a 1366×768 screen
- Board/overlay checks: drive with real `page.mouse` input, not `dispatchEvent` (synthetic events once hid an overlay swallowing taps)
- Long one-line statements (some over 200 characters in `game-video-core.jsx`, `queen.jsx`, `chess-core.js`) are known debt from the 2026-10-17 tech-debt audit: split them only in code you are already changing, never in a sweep of their own
- Render's deploy build runs the full test suite, real-Stockfish test included, on purpose: it stops a broken push going live. If that test ever fails a deploy spuriously, skip just it in the deploy build and leave it to GitHub Actions

## Gotchas
- Layout lives in `LayoutCore` (`app/layout-core.js`): pure `compute({ w, h, text, view, video, cols })` → boxes for board, bars and panels, one column or two (`columns()` decides; `Stage` in `app/engine.jsx` holds the hysteresis and gives views `useFrame()`). Views read `L` (set by `setLayout` in `app/game-video-core.jsx`) and size text with `tx(px)` (times the Text size setting); the board is a 768 px picture scaled into `L.board` (`BoardSpace`), positioned in board pixels. The `.stage-one`/`.stage-short` classes in `app/shell.html` carry the one-column and small-window CSS. A video (playing or exporting) fits the window exactly; the paused one-column page scrolls
- The Full screen menu item shows only where `document.fullscreenEnabled` (or the `webkit` one) is true: not on iPhone Safari, whose way out of the bars is Add to Home Screen (the manifest)
- Settings defaults are `window.TWEAK_DEFAULTS` in `app/shell.html`; viewers' changed settings persist in localStorage and override new defaults
- Move numbers and sides come from `M.ply0` (`ChessCore.moveNo`), never `i % 2`; squares become pixels only through `view()` (the board can be flipped)
- The free board (the dock's Play/Explore menu: Starting position, Edit position; stored files `{ board: { fen, moves, upto } }`, `app/free-board.jsx`, state in `BoardCore` (`app/board-core.js`)) is a separate view from `GameVideo`: the replay's timeline never sees a zero-ply game. Both take board input through `useBoardInput`; the transport bar runs in `still` mode there
- Edit position (Play/Explore › Edit position, which replaced Paste FEN) is a third view, `EditBoard` (`app/edit-board.jsx`, its own pointer input `useEditInput`, unclamped so a drag off the board removes a piece), rules and messages in `EditCore` (`app/edit-core.js`, setups `{ b, turn, castle, ep, half, full }`, any placement allowed, `problems()` says what's wrong); `GameApp` shows it in place of `FreeBoard`/`GameVideo` while `editing` is set, and `commit` clears it
- A game (Play vs human, Play vs Stockfish) is a free board with a game record (`board.game`, rules and clocks in `PlayCore`, `app/play-core.js`), stored with the board. A Stockfish game has `mode: 'stockfish'`, `you` (the player's side) and `critique` (the player's flagged moves, `{ j, cls, best, text }`); `useEngineOpponent` (`app/free-board.jsx`) plays Stockfish's side at the engine's `play` priority (`SFEngine` picks `play`, then `own`, then `game`, but never interrupts a running search, so the player's move stops the "before" search). During a game `FreeBoard` draws no eval bar or explorer (the spec's anti-goal), and a vs-human game starts no search; the board is drawn from `you` in a Stockfish game, else turned to the side to move, whatever Flip says
- My games: each game (`board.game.id`) is kept from its first move under `chess-video.games.v1` (`GamesCore`, `app/games-core.js`; the 50 newest, as `BoardCore.save` boards) by `commitBoard` when the game changes (a move, takeback or result; not stepping through it), reading the stored list afresh each time; `GamesCore.read` checks only the shape (it runs on every move), `GamesCore.playable` restores an entry for the dialog. A finished game opens as a loaded game from `PlayCore.pgn`; the crash screen's Clear saved data leaves the list alone
- Hugging Face sign-in returns to the folder the page is served from (`HF_OAUTH.redirect` in `app/queen.jsx`); every such URL must also be listed in the HF OAuth app's redirect URLs (huggingface.co/settings/applications), exactly, trailing slash included
- Lichess opening explorer (`app/explorer.jsx`, Settings › Online, off by default): `explorer.lichess.ovh` answers 401 without a token (checked 2026-10-28), so the panel signs in by OAuth2 + PKCE (`lichess.org/oauth`, `/api/token`, client id `chess-replay`, no registration or scopes, redirect = the page's folder, any URL works) or takes a pasted personal token; the token is in `chess-video.lichess-auth.v1` (kept by Clear saved data like the HF one) and goes only to Lichess. Its OAuth `state` starts with `lichess.` so the HF handler in `queen.jsx` skips it (both return `?code=&state=`). The response shape in `LichessCore.parseExplorer` and `tests/fixtures/explorer-e4.json` comes from Lichess's documentation, not a live answer: no token was at hand (**verify**). The live test fakes the endpoint with a route, and Playwright's WebKit does not route the CORS preflight and its Firefox hides `Authorization`, so the page's own `fetch` is replaced for that host instead
- Ask Queen calls the user's HF Space boneyland/queen-pawn-8 (`gr3_queen_pawn_8_analyse_position`, `{fen, moves}`) through its Gradio API (`analyse_position`, `directCall` in `app/queen.jsx`); its answer is a Python dict repr (`pyParse` in `app/queen-core.js`). ZeroGPU quota is small (~20–33 s per position): never suggest whole-game Queen runs without the cost
- Not on Netlify: dropped 2026-10-18 (production deploys cost credits, which ran out, and publishing was manual). Don't add Netlify config back
- Not on Codeberg: its Terms of Use (§ 2 (1) 7) forbid projects mostly written by generative AI, which this one is (tried and taken down 2026-10-17)
- Full Stockfish (the Analysis panel's engine drop-down › Full, site only): stockfish.js v19.0.1 `single` (99 MB wasm) is not in git; the browser fetches it from unpkg on the viewer's click, checks the SHA-256s pinned in `app/sf-full.js` (also in LAYOUT.md), keeps it in the cache `stockfish-full-19` (outside `sw.js`'s `chess-replay-*` cleanup) and starts it from Blob URLs. Lite runs until it is kept. The engine name (`AnalysisCore.ENGINE_NAMES`) keys partial runs, the own-move eval cache and the pace estimate, so lite and full results never mix. A Playwright route can't fulfill a body that big (Chromium drops the connection), so the live test downloads the real files
- `vendor/` is stockfish.js v19.0.1 lite-single (GPL-3.0) and the WebP export's encoder (libwebp 1.1.0 in WebAssembly, from @jsquash/webp 1.5.0, its deblocking filter off in `WEBP_CONFIG` in `app/export.jsx`: the browser's own `toBlob` encoder blurred some frames) and the MP4 export's muxer (Mediabunny 1.61.0, `mediabunny.min.js`: an `import()` can't carry an integrity hash, so it isn't loaded from a CDN), pinned by SHA-256 in LAYOUT.md; the site serves them next to the page (`VENDOR` in `build.cjs`); `openings/` is a copy of chess-animator's Lichess tables
- Content-Security-Policy: a `<meta>` that `build.cjs` writes into the page, with a SHA-256 for each inline `<script>` (no `'unsafe-inline'` for scripts) and every host the page talks to. A new host (a CDN, an API) goes in its `connect-src`/`script-src` or the browser blocks it; the live tests turn any `securitypolicyviolation` into a console error. Its `script-src` names each CDN script by its exact URL (taken from `shell.html` and `export.jsx`), never a whole host. Other headers (nosniff, Referrer-Policy, and `frame-ancestors 'self'` + `X-Frame-Options: SAMEORIGIN`: no other site may frame the page, the old notes-site embed was dropped 2026-10-30) are in `render.yaml`, which `tests/live/serve.cjs` reads
- Ask Queen's Sign in with Hugging Face is hidden on Render's PR previews (`HF_PREVIEW` in `app/queen.jsx`): their hosts aren't redirect URLs of the OAuth app
- Offline: the site's `sw.js` keeps the page (network first) and everything it loads, CDN files and fonts included (from the copy first). Its `VERSION` is a hash of those files, so a deploy that changes one replaces the copy; a new CDN URL in `shell.html` or `export.jsx` is picked up by `build.cjs`. Playwright's offline emulation in Firefox fails `no-store` requests a service worker answers; stopping the server is the real test
- `docs/spec.md` is the one spec: principles, what's built, the roadmap (planned features, open questions marked), known gaps and a decisions log; update it when a feature is designed, built or decided. `docs/plans/` holds the implementation plans of built features, kept as written (the oldest predates the split; its paths were rewritten to repo-root ones)
- `games/` (local PGNs) and `.superpowers/` (scratch) are untracked; never commit them
